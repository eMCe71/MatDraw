### 1.2 Helpers (XSS conventions)
- `esc` (l.18): `const esc=s=>String(s??'').replace(/[&<>"']/g,c=>({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]));`
  - Convention: the whole UI is template strings assigned to `innerHTML`. EVERY user/server value must go through `esc()` (names, clubs, emails, tournament names, error text via `textContent`). ### 1.3 Routing: `render()`, `navigate()`, hash
- Routing is hash-based, no router library. `ui.page` is the page id; `location.hash` mirrors it (`#tournaments`, `#database`, `#accounts`, `#overview`, `#athletes`, `#checkin`, `#draws`, `#rules`, `#architecture`). Special hashes: `#screen?tournament=ID&category=ID` (hall screen) and `#guest?t=ID` (guest preview).
- `render()` (l.79-89):
  ```js
  function render(){
   if(!workspace){renderPublic();return;}
   syncState();if(location.hash.startsWith('#screen')&&workspace.user.role!=='club'){renderScreen();return;}
   if(location.hash.startsWith('#guest')){ui.page='tournaments';history.replaceState(null,'','#tournaments');}
   document.body.classList.remove('projection');
  ```

  IMPORTANT: `render()` replaces the WHOLE `#app` innerHTML. Any live chat DOM inside `#app` is destroyed (scroll position, typed draft, focus) on every `render()`. `render()` is called by many paths: every commit, language change, `storage` event, `hashchange`, `refresh`, filter inputs (`filterRender`, l.380 keeps caret). A chat mounted in `#app` must be re-attached from a state object (like `upcoming`/`paintUpcoming`) or live in a sibling root outside `#app`.
  - Unknown `ui.page` (e.g. `chat`) silently falls back to `tournamentsPage`; so a new page must be added to the `pages` map AND to the title map AND (for the sidebar) to `shell()`.
- `navigate(page)` (l.90): `ui.page=page;ui.menu=false;history.replaceState(null,'','#'+page);render();window.scrollTo({top:0});` (uses `replaceState`, so the browser Back button does not step through pages).

### 1.11 `commit()`, `syncState()`, `handleError()`, revision / 409
```js
async function commit(type,payload,expected=Number(document.querySelector('.modal')?.dataset.revision||workspace.revision)){
 if(saving)throw Error('Trwa zapisywanie. Poczekaj na potwierdzenie.');
 saving=true;
 try{const res=await Client.command(type,payload,expected);workspace=res.workspace;syncState();return res.result;}
 finally{saving=false;}
}                                                                                  // l.307-312
async function handleError(error,form){
 if(error.status===401){workspace=null;closeModal();renderLogin(error.message);return;}
 if(error.status===409){try{workspace=await Client.bootstrap();syncState();render();if(form)form.dataset.revision=workspace.revision;const dialog=document.querySelector('.modal');if(dialog)dialog.dataset.revision=workspace.revision;}catch{}}
 const message=translateMessage(error.message),box=form?.querySelector('.form-error')||document.querySelector('.form-error');if(box)box.textContent=message;else toast(message);
}                                                                                  // l.313-317
```
- Optimistic concurrency: the server keeps ONE global counter `app_meta.revision`. Every command carries `expectedRevision`; the server rejects a mismatch with HTTP 409 "Dane zmieniły się w innej sesji. Odśwież widok i ponów zapis.", every successful command does `revision++` (`Domain::execute`). Forms remember the revision they were opened with (`data-revision` on `.modal` and `<form>`). On 409 the client reloads the whole workspace and the user must retry. All writes are serialized (see 5.3).

- Chat messages MUST NOT use `commit()`/`expectedRevision`/`app_meta.revision` (a chat message would invalidate every open form of every user and serialize on the global lock).

### 3.2 What the test enforces (each rule, scope, mechanics)
Helpers: `literal="'((?:[^'\\\\]|\\\\.)*)'"` (single-quoted JS string with escapes), `all(source,pattern)` = all regex group-1 matches, `POLISH_LETTERS=/[ąćęłńóśźżĄĆĘŁŃÓŚŹŻ]/`, `NAMES=/Bogusław/g`.
1. Language detection (l.22-32): `detectLanguage`/`resolveLanguage`/`STORAGE_KEY==='matdraw.language'`.

## 5. Backend

### 5.1 Request flow: `backend/public/api/index.php` (63 lines)
Everything goes through ONE front controller `?route=<name>`; no router, no middleware layer. Sequence:
1. `require dirname(__DIR__,2).'/backend/bootstrap.php'` (release layout: `public/api/index.php`, sibling `backend/`). Headers for every response: `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store, private`, `X-Content-Type-Options: nosniff` (l.7-8). `respond($value,$status)` = `http_response_code + json_encode(JSON_THROW_ON_ERROR|JSON_UNESCAPED_UNICODE) + exit` (l.9).
2. `matdraw_config()` then `$route=$_GET['route']??'session'` (l.27).
3. PUBLIC routes first (l.28 -> `respond_public`, l.12-25): `route=public` and `route=public-tournament&id=` run BEFORE `Auth::start()`: GET only (else 405 + `Allow: GET`), no session/cookie/CSRF, builds `new Repository(matdraw_database($config))`, `GuestView::upcoming(...)` / `GuestView::tournament(...)`, then `header('Cache-Control: public, max-age=60')`. Errors: `AppError` -> `{error}` with its status; `Throwable` -> logs `MatDraw: Class message` and returns `{error:'Błąd serwera. Skontaktuj się z Administratorem.'}` 500. Id check regex `/^[A-Za-z0-9_-]{1,40}$/D`.
4. `Auth::start($config)` (l.29) is called for EVERY other route, including unknown ones (it creates a session). `$methods=['session'=>'GET','bootstrap'=>'GET','login'=>'POST','logout'=>'POST','command'=>'POST']` (l.31); unknown -> 404 `Nie ma takiej operacji.`, wrong method -> 405 with `Allow`.
5. POST pipeline (l.35-41): `Auth::requireCsrf($config)`; `Content-Type` must start with `application/json` (415); body <= 65536 bytes by `CONTENT_LENGTH` and by reading 65537 bytes (413); `json_decode(...,depth 32)` (400 on failure); must be an array.
6. `logout` (l.42): `Auth::clear()`. `command` (l.43-48): `$repo->transaction(fn(&$db)=>{$u=Auth::current($db); $result=Domain::execute($db,$u['id'],$p['type'],$p['payload'],$p['expectedRevision']); $after=...; return ['workspace'=>$after['active']?Domain::publicData($db,$after):null,'result'=>$result,'authVersion'=>...];})`; a deactivated actor gets 401 and `Auth::clear()`; else `$_SESSION['authVersion']=...`, respond `{workspace,result}`. `login` (l.49-58): lowercases email, length caps, `Auth::reserveLogin`, `$repo->transaction` over the whole workspace to find the user and `password_verify` (fixed dummy bcrypt hash for unknown accounts), then `Auth::enter($u)` and respond `{user,csrf}`.
7. `session`/`bootstrap` (l.59-61): `$db=$repo->snapshot(); $u=Auth::current($db,$route!=='session')`; `session` -> `{user|null,csrf}`; `bootstrap` -> `Domain::publicData($db,$u)`.
8. Errors: `AppError` -> `{error,csrf}` + status; anything else -> logged, generic 500. All user-visible server messages are Polish literals.
- Facts that matter for chat/billing: (a) `session` AND `bootstrap` both call `snapshot()` = full table scan of everything; (b) the identity check `Auth::current` iterates an in-memory users list, so a lean variant querying one row is needed; (c) POST body limit is 64 KB (fine for chat, not for avatar upload: use multipart or base64 in a separate endpoint with its own limit); (d) a Stripe webhook (POST, signed raw body, no cookie/CSRF/Origin) must be routed like the public routes, BEFORE `Auth::start()` and before the POST pipeline; (e) `Origin` is only checked when the header is present (`Auth::requireCsrf`), plus the CSRF token.

### 5.2 `Auth.php` (37 lines)
- `Auth::start(array $c)`: strict session ini (`use_strict_mode`, `use_only_cookies`, `use_trans_sid=0`, `gc_maxlifetime=session_max_seconds`), `session_name('matdraw_session')`, cookie params `lifetime 0, path /, secure iff app_url is https, httponly, samesite Strict`, `session_start()` (PHP FILE sessions, default `session.save_path`). Expires `userId` sessions on idle (`session_idle_seconds` 1800) or absolute (`session_max_seconds` 43200) via `self::clear()`. Always sets `$_SESSION['csrf']??=bin2hex(random_bytes(32)); $_SESSION['last']=$now;`.
  - GOTCHA 1: `session_start()` takes an exclusive lock on the session file until the request ends; nothing calls `session_write_close()`. Concurrent requests of one browser (2 s polls from several tabs plus a command) are serialized. Read-only polling endpoints should read `userId`/`authVersion` and call `session_write_close()` immediately.
  - GOTCHA 2: every request sets `$_SESSION['last']=time()`, so a tab that polls keeps the session "active" for the full 12 h `session_max_seconds` and defeats the 30-min idle timeout. Polling routes must not refresh `last`.
- `Auth::clear()` -> `$_SESSION=[]; session_regenerate_id(true); new csrf`. `Auth::enter(array $u)` -> regenerate id, store `userId, authVersion, created, last, csrf`.
- `Auth::requireCsrf(array $c)`: if `HTTP_ORIGIN` is present it must equal `scheme://host[:port]` of `app_url` (403 `Niedozwolone źródło żądania.`), and `X-CSRF-Token` must `hash_equals` the session token (403 `Sesja formularza wygasła. Odśwież stronę.`).
- `Auth::current(array $db,bool $required=true)`: session `userId` must match an ACTIVE user whose `authVersion` equals `$_SESSION['authVersion']`; otherwise clears the session and throws 401 `Zaloguj się ponownie.` (or returns null). `authVersion` is bumped on password/role/club/active/email change: that is how other sessions of the account are invalidated.
- `Auth::reserveLogin(PDO,array $c,string $email)`: throttle in table `login_limits` (HMAC-SHA256 of `ip` and `ip|email` with `app_key` as bucket, 15 min window, 40/IP and 8/IP+email, atomic `INSERT ... ON DUPLICATE KEY UPDATE`), 429 `Zbyt wiele prób logowania. Spróbuj ponownie za 15 minut.`; also deletes buckets older than 24 h. Reusable pattern for chat flood limits and checkout/sign-up throttles. `REMOTE_ADDR` behind the host's proxy is UNVERIFIED (if the host proxies, all users could share one IP bucket).
- No email, no password reset, no signup, no "remember me".

### 5.3 `Repository.php` (76 lines): global write lock and snapshot
```php
public function snapshot():array {            // l.11: BEGIN; load(); COMMIT
public function transaction(callable $fn):mixed { // l.15
  BEGIN; SELECT revision FROM app_meta WHERE id=1 FOR UPDATE;   // global mutex
  $before=$this->load();$next=$before;$result=$fn($next);$this->persist($before,$next);COMMIT;
public function guestTournaments(string $today,?string $id=null):array  // l.27
private function load():array   // l.42: schemaVersion 2, revision, clubs, users, profiles (athletes), tournaments(+entries,+draws)

```
- `transaction()` loads the ENTIRE workspace (all clubs, users, athlete profiles, tournaments, entries, draws), runs the callback, diffs rows (`rows()` before vs after), upserts changed rows (`INSERT ... ON DUPLICATE KEY UPDATE col=VALUES(col)`), deletes only removed `entries` and `draws`, sets `app_meta.revision`. The `FOR UPDATE` on `app_meta` row serializes ALL writes of the whole app (and logins, which also use `transaction()`), and `Domain::execute` increments `revision` for each command.
- `snapshot()` (reads, no lock) is used by `session`, `bootstrap`.
- Rows are keyed by explicit column lists: `users` columns mapped in `load()` l.45 and `rows()` l.56 are `id, club_id, email, role, active, password_hash, auth_version`. Extra columns added to `users` are invisible to `load()`/`persist()`, and `persist()`'s `INSERT` of a NEW user would fail unless the extra columns are NULLable or have defaults. A separate table keyed by `user_id` avoids touching these functions.
- `guestTournaments` is the model for lean public reads (selects only id,name,city,event_date,status; entries/draws only for the one requested tournament).
- SQL compatibility: `VALUES(col)` in upserts works in MariaDB 10.6 and MySQL 8.0 (deprecated warning in MySQL >= 8.0.20); JSON columns on MariaDB are LONGTEXT aliases. Keep new SQL to the common subset (no `RETURNING`, no JSON functions, no window functions beyond 10.6/8.0 parity checks).
- Rule: chat, billing and member-profile data must use their own repository classes with lean, indexed queries and NOT call `transaction()`/`snapshot()`.

### 5.4 `Domain.php` (89 lines): commands and `publicData`
- `AppError(message,status=422)` extends RuntimeException (Domain.php:4). Helpers: `Domain::id()` (32 hex), `txt($v,$label,$max=100)` -> `Sprawdź pole: <label>.`, `number`, `date`, `ageAt`, `entity(&$rows,$id,$label)` (404 `<label> nie istnieje.`), `manages`, `managesProfile`, `canEnter`, `safeUser` (drops `passwordHash`, `passwordSalt`, `authVersion`), `password()` (12-72 bytes, Argon2id if available).
- `Domain::execute(&$db,$actorId,$type,$p,$revision)` (l.24): actor must exist and be active (403), `$revision===$db['revision']` else 409, `apply(...)`, `$db['revision']++`.
- Command types in `apply()` (l.28-87) in dispatch order: `account.password`, `account.save` (admin only; validates email, uniqueness, role in `['admin','editor','club']`, last-admin guard, club resolution/creation, bumps `authVersion` on identity change), `tournament.save` (admin/editor), `profile.save` (athlete record, optional embedded `registration`), `profile.archive`, then (all need `p.tournamentId`, loaded as `$t`) `entry.save`, `entry.remove`, then (need `manages($u,$t)` and non-finished) `checkin.save`, `draw.create`, `result.save`, `result.clear`; anything else -> 400 `Nieznana operacja.`.
- DANGER for new roles: `apply()` authorizes by negative role checks. `publicData` treats every role other than `club` as "sees everything not draft"; `canEnter` allows any non-finished OPEN tournament for any user; `profile.save` takes `$p['clubId']` for any non-club role. A new account type stored in `users.role` (e.g. `member`/`fan`) would be able to read all athletes (names, birth dates, weights) and create/enter athletes unless every guard is rewritten to allow-lists. Recommendation: keep paid/free access, username, country, sport, avatar OUTSIDE `users.role` (separate tables), or add an explicit `if(!in_array($u['role'],['admin','editor','club'],true))throw new AppError('Brak uprawnień.',403);` at the top of `apply()` and in `publicData`.
- `publicData(array $db,array $u)` (l.16-20) response shape: `{schemaVersion:2, revision, user:safeUser($u), clubs:[...], users:(admin? all safeUser : []), profiles:[athletes visible to the user], tournaments:[...]}`. Club role: own club only, own entries only, `draws:[]`/`activity:[]`, hides drafts and closed tournaments without own entries. `draws` is cast to an object (`results` too). Tournament object: `id, createdBy, name, city, date, mat, status, activity[{text,time}], entries[{id,profileId,clubId,name,club,sex,age,weight,height,gradeType,grade,events,champion,presence,actualWeight}], draws{categoryKey:{size,slots,results,signature,revision,...}}`. `safeUser` keys today: `id, clubId, email, role, active`.

### Quick facts worth remembering while designing
- No signup route, no email, no password recovery exist. `users.club_id` is NOT NULL and `account.save` requires a club (self-service accounts need a default/personal club or a nullable column + changes in `Repository` mapping and `Domain`).
- Roles `admin|editor|club` are used for authorization everywhere; "free by admin" and "paid" should be a separate attribute/table, not a role.
- `Domain::publicData` ships all visible athletes (with birth date, weight) to the browser; chat/profile modules must not widen that.
- Every full-workspace request (`session`, `bootstrap`, `login`, every command) costs O(all data); the hall screen already polls it every 15 s. Chat polling must be an independent lean route.
- `date('Y-m-d')`/`warsawToday()` are Warsaw dates; chat timestamps should be stored UTC (`gmdate`) and formatted with `locale()` at display.
- English strings may not contain Polish letters (test), so country/sport labels should use `Intl.DisplayNames` / plain ASCII keys, and emoji flags in channel names ("Taekwondo 🌎") are fine in keys (the Polish-letter regex is letter based).
